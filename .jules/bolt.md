## 2026-09-26 - Subquery Join Elimination & Aggregation Batching in Laravel Dashboards
**Learning:** Performing multiple `whereHas` subqueries across deep relationships (e.g. `Order::whereHas('items.product', fn($q) => $q->where('shop_id', $shopId))`) repeatedly triggers subqueries with table joins for every single aggregate calculation (`total_orders`, `pending_orders`, `total_revenue`, `recent_orders`). Fetching parent entity IDs (`Product::where('shop_id', $shopId)->pluck('id')`) upfront allows direct `whereIn` filtering on child tables (`OrderItem`), eliminates subquery joins on intermediate tables (`products`), allows early exit when ID count is 0, and enables combining multiple column aggregates (`AVG` and `COUNT`) into a single `selectRaw` query.
**Action:** When calculating dashboard overview metrics across Eloquent relationships, query the primary child key list once upfront to eliminate repeated relational subqueries and batch aggregate calculations.
